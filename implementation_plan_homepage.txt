# FitFreak - New Home Page with 3D Muscle Map

Status: Phases 1-5 implemented (written 2026-10-29; Phase 1 EAS preview APK build and Phase 6 optional extras remain unchecked).
Work through the phases in order (Phase 4 can run alongside Phase 3). Tick the [ ] boxes as
work lands; each phase ends with a "Done when" check.


## Goal

- A new Home tab showing a 3D body with every major muscle. Muscles trained in the chosen
  period light up: the more sets, the brighter.
- A Daily / Weekly switch picks the period.
- Everything the app does today (workout log + active workout) moves, unchanged, to a new
  Workout tab.


## Starting point

- One bottom tab, "Home". src/core/HomeTab.tsx shows ActiveWorkoutScreen while a workout is
  running, otherwise WorkoutLogScreen.
- Each CompletedWorkout is one exercise: `name`, muscle group `category`, `totalSets` (completed
  sets only) and `startTime`. That is enough to work out which muscles were trained, so the
  backend needs no changes.
- At launch, historyStore.fetchData() loads the last 7 days of workouts, so "today" and "this
  week" are always in memory.
- Bug to fix first: MUSCLE_GROUPS (the list that target-muscle chips and workout categories are
  picked from) spells Forearm, Abs and Core, but DEFAULT_MUSCLE_EXERCISES uses Forearms and
  Abs/Core. Picking Forearm, Abs or Core shows no built-in exercises. The muscle map depends on
  these names matching. Both lists are in src/constants/exercises.ts.
- expo-asset and expo-file-system are only installed inside node_modules/expo/node_modules.
  React Three Fiber needs them at the top level.


## Decisions

| Topic                | Decision                                                           |
|----------------------|--------------------------------------------------------------------|
| What lights up       | Completed workouts (what was done), not the target-muscle chips    |
| "Weekly"             | Current calendar week, Monday to Sunday                            |
| Brightness           | Completed sets: 1 per set for main muscles, 0.5 for helper muscles |
| Level of detail      | About 30 visible muscles; left and right are separate meshes       |
| Where old screens go | A second bottom tab, "Workout"                                     |
| 3D library           | React Three Fiber 9.x + drei 10.x + expo-gl (works in Expo Go)     |
| 3D model             | Z-Anatomy (free, CC BY-SA 4.0)                                     |
| Backend              | No changes for v1                                                  |

## Phase 4 - Prepare the 3D model from Z-Anatomy (longest step; can run alongside Phase 3)

Source: Z-Anatomy, "The libre 3D atlas of anatomy". Every muscle is its own object.
  - Blender template: https://github.com/Z-Anatomy/Models-of-human-anatomy
    Follow its README: install Z-Anatomy.zip as a Blender application template, then
    File > New > Z-Anatomy. The README's examples use Blender 3.1/3.2.
  - FBX exports, if the template is awkward: https://github.com/LluisV/Z-Anatomy
    (branch PC-Version, folder Resources/Models/FBX)
  - Option A (used): https://github.com/tiralonghipol/free-muscles (`public/anatomy.glb`),
    a pre-separated Z-Anatomy GLB export preserving `userData` metadata (`kind`, `label`,
    `side`, `group`).

License (CC BY-SA 4.0) - required:
  - Credit both in the app and in the repo:
      "Z-Anatomy - The libre 3D atlas of anatomy - CC-BY-SA 4.0"
      "BodyParts3D - The Database Center for Life Science - CC-BY-SA 2.1 Japan"
  - The edited model (body.glb) must stay under CC BY-SA 4.0. Keep a license note next to it.
  - Use only muscles plus a neutral base. A few Z-Anatomy extras (e.g. the inner ear and kidney
    models) are non-commercial-only; leave them out.

Model preparation steps (completed via Option A: `free-muscles` + `@gltf-transform` + `src/constants/anatomyMap.ts`, without manual Blender edits):
- [x] Keep the outer layer of the muscles in 3a, plus one neutral base mesh (skin or skeleton)
      for the head, hands, feet and joints.
      (Option A: `free-muscles` provides muscles plus neutral skeleton/connective meshes
      without non-commercial extras; deep/sub-muscles map onto superficial `MuscleId`s via
      `src/constants/anatomyMap.ts`.)
- [x] Join the objects that make up one app muscle, per side. Example: rectus femoris + the
      three vasti -> quadriceps_l. If a muscle that 3a splits (upper/lower chest, trapezius
      parts) comes as one object, separate it (Edit Mode > select faces > P > Selection), or
      merge those IDs in muscles.ts.
      (Option A: kept the ~155 unique `free-muscles` muscle labels across 325 muscle meshes
      and rolled them up onto all 31 `MuscleId`s in `src/constants/anatomyMap.ts` instead of
      joining/splitting meshes in Blender.)
- [x] Name the objects <muscleId>_l or <muscleId>_r (three.js uses object names, not mesh-data
      names), using only lowercase letters, digits and underscores. three.js strips
      . : / [ ] from names, so Blender's "Deltoid.L" or ".001" suffixes arrive mangled.
      (Option A: preserved glTF node `extras`/`userData.label` from `free-muscles` and
      mapped all 31 `MuscleId`s via `resolveAnatomyMuscleId()` in
      `src/constants/anatomyMap.ts` instead of Blender `<muscleId>_l` / `_r` renaming.)
- [x] One material per object, so each muscle loads as a single mesh.
      (Verified: 666 single-mesh nodes with 0 embedded materials; shared `theme.colors.anatomy`
      materials are created and assigned at runtime in `src/features/home/BodyModel.tsx`.)
- [x] Apply all transforms. Y-up, about 1.8 units tall, facing +Z (glTF's "front").
      (Option A: `free-muscles` GLB is Y-up, ~1.7-1.8 units tall, facing +Z as exported,
      with original node transforms preserved rather than baked in Blender.)
- [x] Decimate to 50-80k triangles in total. Delete UVs, textures, bones and shape keys; the app
      sets colors itself.
      (Verified: vertex-decimated via `@gltf-transform` to 78,693 triangles total with 0
      materials, 0 textures, 0 UVs, 0 skins, and 0 animations.)
- [x] Export as glTF Binary (.glb), then optimize:
        npx @gltf-transform/cli weld body-raw.glb body-welded.glb
        npx @gltf-transform/cli quantize body-welded.glb body.glb
        npx @gltf-transform/cli inspect body.glb      (check names and triangle count)
      Do NOT use Draco or Meshopt compression: their decoders need WebAssembly or Web Workers,
      which React Native doesn't have.
      (Option A: Draco-decompressed and decimated `free-muscles` GLB via `@gltf-transform`
      into uncompressed glTF 2.0 binary with zero `extensionsUsed` / `extensionsRequired`.)
- [x] Save as assets/models/body.glb (target: 3 MB or less) with its license note.
      (Verified: `assets/models/body.glb` is 2.48 MB / 2.37 MiB paired with
      `assets/models/LICENSE.txt` with CC BY-SA 4.0, Z-Anatomy, BodyParts3D, and
      `free-muscles` attribution.)

Done when: body.glb loads on the Phase 1 test screen and every muscle in 3a is found by name
(or mapped via `src/constants/anatomyMap.ts` — verified: all 31 `MuscleId`s mapped and loaded).

## Risks

- The model. Cleaning up Z-Anatomy is the biggest unknown. BodyViewer only receives a level per
  muscle, so a 2D front/back SVG map (react-native-svg is already installed) could replace it
  without changing any Phase 3 code.
- 3D on Android. expo-gl can misbehave on some devices and emulators; Phase 1 is there to catch
  this early.
- Pinch-zoom through OrbitControls may be unreliable with React Native touch. Rotation matters
  most, so drop zoom if needed.
- Custom or renamed exercises light up at the group level only (e.g. all of Back) until the
  Phase 6 muscle tagging.
- App size grows by the model (target 3 MB or less) plus three.js.


## How to verify

- `npm run typecheck` and `npx expo export`.
- Log 3 completed sets of Barbell Bench Press. Daily: lower chest brightest, front delts and
  triceps lighter. Weekly: also shows earlier days this week. Deleting the workout clears it.
- Mixed/Other with a custom name is counted as "not shown on the body". Cardio lights nothing.
  Full Body lights everything faintly.
- Rotating never selects a muscle. Switching tabs many times doesn't crash or reload the model.
- On Monday the weekly view starts empty; on Sunday it still shows the whole week.
- Preview APK on a low-end Android phone: the model loads in about 1-2 seconds and rotates
  smoothly.
